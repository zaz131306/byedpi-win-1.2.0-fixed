# Режим «белых списков» — что это, чем отличается от обычной блокировки, и что делать

> Разобрано 5 ресурсов, которые вы прислали. Все проверены на живость **2026-10-29** из рабочей
> песочницы (данные ниже — фактические, не «по памяти»). Рядом лежит `VPN.md` — про VPN вообще.

---

## 0. Главное: это ДРУГОЙ тип блокировки

| | Обычная блокировка (чёрные списки) | Режим белых списков |
|---|---|---|
| Как работает | Режут **конкретные** сайты/протоколы | Пропускают **только** разрешённое, всё остальное не работает |
| Симптомы | Часть сайтов не открывается | Не открывается **почти всё**, работает только «одобренное» |
| Где | Домашний интернет, повсеместно | Мобильный интернет, отдельные регионы, периоды «беспилотной опасности» |
| Лечится byedpi? | **Да** — это его работа | **Нет. Физически.** |

**Почему byedpi тут бессилен** — и это не ограничение моей сборки:

byedpi маскирует *содержимое* пакетов уже установленного соединения. В режиме белых списков
фильтр принимает решение *до* этого: он смотрит на SNI (имя сайта) в ClientHello и на
IP-адрес назначения. Если сайта нет в белом списке — соединение не пускают вообще, и никакие
`+sh`, `+s2`, `md5sig`, fragment, fake TLS или 73 стратегии перебора не помогут: **нечего
маскировать, пакет не доходит.**

Отсюда практический вывод:

> **Сначала определите, в каком вы режиме.** Один тест: откройте сайт, который точно в белом
> списке (например `gosuslugi.ru`) и сайт, которого там точно нет. Если первый работает, а второй
> нет **и при этом второй не работает даже через заведомо живой VPN** — вы в белых списках.
> Тогда нужны не аргументы byedpi, а **канал, который сам проходит через белый список**.

Именно такие каналы и лежат в присланных вами ссылках. Дальше — по каждой.

**В чём здесь соль** (это и есть механизм обхода БС):

* **REALITY-профили на российских хостингах** используют как SNI **белые российские домены** —
  `ya.ru`, `max.ru`, `io.ozone.ru`. Для фильтра handshake выглядит как обращение к Яндексу/MAX/
  Ozon, то есть к разрешённому ресурсу. Трафик при этом шифруется и уходит на сервер.
* **xhttp + CDN-хосты** (`rucdncomp.pro`, `bakarova-top.ru`) — входные точки CDN. Их нельзя
  заблокировать точечно, потому что за одним IP стоит множество клиентов (подробнее в п. 4).
* **4 профиля на `raw` с `security=reality`** на Beget — прямое TCP с маскировкой под белый сайт.

**Как пользоваться (Windows):**

1. Клиент: **Throne** или **v2rayN** (оба поддерживают VLESS + REALITY + xhttp).
2. Добавить подписку:
   `https://raw.githubusercontent.com/zieng2/wl/main/vless_universal.txt`
   Зеркала (работают, когда GitHub закрыт): Codeberg, GitLab, `hub.mos.ru`, `gitverse.ru`.
3. **Обязательно** включить режим **балансировщика / автовыбора узла** — конфиги живут от пары минут
   до суток, руками вы не успеете перебирать.
4. Если ничего не коннектится — включить **«Разрешить небезопасные» / Allow insecure**.
   ⚠️ Это **отключает проверку сертификата сервера**: пул рабочих узлов резко расширяется, но
   появляется риск MITM. Для «просто открыть сайт» приемлемо, для банков/логинов — нет.
5. **Отключите** в Karing/Hiddify правило «обходить российские сайты напрямую» — оно ломает
   профили, которые как раз и маскируются под российские домены.

**Риски, честно:** бесплатный сервер = владелец видит весь ваш трафик (кроме того, что защищено
end-to-end, например HTTPS внутри). Не заходите через него в банк, Госуслуги, рабочую почту.
И это публичная подписка — узлы могут выжигать десятками людей одновременно.

**Отдельно отмечу `trojan` и `hysteria2` в подписке.** `hysteria2` работает по **QUIC/UDP**. Если
фильтр режет в основном TCP (а byedpi — он именно про TCP), UDP-туннель может пройти там, где все
TCP-конфиги легли. Это ваш запасной вариант номер один.

**Два приёма из их README, которые стоит знать отдельно:**

* **Яндекс Переводчик как прокси.** Если вы в БС и GitHub закрыт, ссылку на RAW-подписку можно
  скормить `translate.yandex.ru/translate` — он fetch'ит её **со своих белых IP** и отдаёт вам текст.
  Работает либо напрямую в клиенте (только связка **Yandex + Bitbucket**), либо копипастом из
  браузера (тогда подходит любое зеркало). Осторожно: остальные зеркала в связке с Яндексом
  **обнуляют параметры** `sni/security/type/pbk/sid/fp/mode` — это целенаправленно сломано, так что
  при автоматическом обновлении используйте только Bitbucket.
* **Зеркала сохраните заранее**: GitHub, GitLab, Codeberg, Gitea, SourceHut, Bitbucket,
  `raw.githack.com`. Их же README предупреждает про возможную блокировку GitHub.

**Форматы:** подписка отдаётся сразу в 10+ форматах — стандартный, base64, Clash/Mihomo, v2rayN,
v2rayNG, Streisand, Happ, V2Box, v2RayTun. То есть под любой клиент, включая Windows.

**Риски:** те же, что у любой бесплатной подписки, плюс объём — тысячи людей на одних узлах.
У проекта есть Telegram-канал `t.me/igareq`, там публикуют свежие ссылки для БС
(README прямо пишет, что BitBucket периодически недоступен и актуальные ссылки — в канале).

## 4. `frank-underwood64/whitelists_bypass` (discussion #1) — своя схема CDN + XHTTP

★ 33 · MIT · обсуждение от 2026-07-27

**Самый технически ценный документ из пяти.** Разбирает, почему старые методы умерли и что пришло
на смену:

| | Старый метод (каскад) | Новый (CDN + XHTTP) |
|---|---|---|
| Путь | Клиент → белый российский IP → зарубежный сервер | Клиент → TLS → **CDN** → TLS → nginx → Xray-core |
| Входных точек | Одна (IP белого сервера) | **Много** — вся сеть CDN |
| Блокируемость | Легко: выжгли IP — всё | Тяжело: придётся блокировать CDN целиком |
| Цена | Взлетела, ненадёжно | **~0,6 ₽/ГБ** трафика CDN |

**Почему это работает в БС:** фильтр видит легитимный TLS к домену за популярным CDN. Такой домен
нельзя заблокировать, не положив разом тысячи сайтов на том же CDN. А XHTTP поверх TLS даёт
трафик, неотличимый от обычных HTTPS-запросов.

**Что нужно, чтобы поднять самому:**

1. VPS с **IPv4** (не все CDN работают с IPv6-ориджинами).
2. **Два домена**: один для входа через CDN, один для источника.
3. **Два TLS-сертификата** (Let's Encrypt сойдёт).
4. Ресурс CDN (Cloudflare / российский CDN).
5. **nginx** как reverse-proxy.
6. **Xray-core** (опционально панель Remnawave для управления ключами).

**Клиенты:** Xray **> 26.6.27**, Happ / INCY **≥ 2.7.11** — старые версии XHTTP не понимают.

**Плюс в том, что это ваш собственный сервер:** никто чужой не видит трафик, не выжигают узлы,
работает стабильно. **Минус:** нужен VPS (~$5/мес), домены и час-другой на настройку.

⚠️ Дисклеймер: автор обсуждения продаёт VPN-услуги, так что текст местами маркетинговый.
Но сама архитектура корректная и совпадает с тем, что я вижу в живых конфигах из п. 1
(там 28 профилей из 52 — именно `xhttp` через CDN-хосты).

## 5. `igareck/.../issues/233` — SlipNet: DNS-туннель как последний рубеж

★ закрыто 2026-05-21 · проект **SlipNet** (`github.com/anonvector/SlipNet`)

**Идея:** весь трафик упаковывается в DNS-запросы. DNS почти всегда разрешён — даже в самых
жёстких режимах его не вырубают, потому что ляжет вообще всё.

**Платформы:** Android, Windows, Linux, macOS (консоль).
**Скорость:** «на уровне текстовых сообщений». Это не для видео и не для нормальной работы —
это аварийный канал: мессенджер, почта, прочитать новость.

**Протоколы:** DNSTT / NoizDNS / VayDNS.

## 6. `lib4u/amnezia-tunneling-ru` — **не** обход БС, а дополнение к вашему AmneziaVPN

★ 468 · списки обновляются **ежедневно**

Это обратная задача: не «открыть заблокированное», а «**не пускать российское через VPN**».
Зачем это нужно именно вам:

* российские банки и Госуслуги **блокируют вход с иностранных IP** — без исключений вы останетесь
  без банка;
* экономит трафик VPS;
* **меньше внимания РКН** — ваш VPN-туннель не тащит через границу гигабайты Ozon и Яндекса.

**Три файла (проверил, живые):**

| Файл | Объём | Для чего |
|---|---|---|
| `amnezia.json` | **277 КБ**, 1900+ доменов, 80 категорий | Десктоп, доменные правила |
| `amnezia-ip-lite.json` | **71 КБ**, ~650 подсетей | **Мобильные** — лёгкий |
| `amnezia-ip.json` | 12 800+ подсетей = **весь российский IPv4** | Только десктоп |

Стабильные ссылки (не меняются):
`https://github.com/lib4u/amnezia-tunneling-ru/releases/download/latest/amnezia.json`
(и так же для `-ip-lite.json`, `-ip.json`).

**Важная деталь из их README:** в Amnezia домены резолвятся **один раз при импорте** и дальше не
обновляются. Поэтому **IP-списки надёжнее доменных** — они не протухают.

**Куда вставлять:** AmneziaVPN → Split tunneling → **Exclude** → импорт файла.

**Чего в списках нет намеренно:** loopback, адрес вашего локального шлюза, CGNAT `100.64.0.0/10`.
Если их исключить из туннеля — VPN просто перестанет подниматься.

⚠️ В шапке README висит рекламный баннер `wpn.me` с referral-параметром. На сами списки не влияет,
но имейте в виду.

## Итоговая карта: что брать и в каком порядке

| Ситуация | Инструмент | Цена | Доверие |
|---|---|---|---|
| Обычная блокировка (ваш rutor.info) | **byedpi** — `verify.py`, `pick_multi.py` | 0 | своё, проверяемое |
| Нужен VPN с исключением российских сайтов | **Amnezia + lib4u IP-списки** | VPS | своё |
| Включились белые списки, надо быстро | **zieng2/wl** (Throne/v2rayN, балансировщик) | 0 | чужие серверы |
| БС надолго / регулярно | **igareck CIDR+SNI подписки** или **свой CDN+XHTTP** | 0 / ~$5+0,6₽/ГБ | чужие / своё |
| Не работает вообще ничего | **SlipNet DNS-туннель** | 0 | минимальное |
| GitHub закрыт, ссылки не открываются | **Яндекс Переводчик как прокси** + зеркала | 0 | — |

**Три правила безопасности для всех бесплатных конфигов:**

1. **Не смешивайте.** Через бесплатный узел — только «почитать». Банки, Госуслуги, рабочая почта —
   только через свой VPN или напрямую.
2. **«Allow insecure» = отключённая проверка сертификата.** Включили — значит, вас может
   слушать кто угодно посередине. Выключайте, когда проблема решена.
3. **Ссылки протухают.** Подписки живут часами, DNSTT-туннели умирают пачками, зеркала
   блокируют. Перед использованием прогоните `WL-check.bat` (см. ниже) — он скажет,
   что живо прямо сейчас.

## Скрипт проверки живости: `WL-check.bat` / `WL-check.sh`

Показывает, какие зеркала подписок отвечают **сейчас** и сколько в подписке живых профилей.
Ничего не устанавливает, ничего не меняет — только читает URL.

```bat
WL-check.bat
```

Состав:

| Файл | Что делает |
|---|---|
| `WL-check.bat` | входная точка для Windows |
| `WL-check.sh` | то же для Linux / macOS / WSL / Git Bash |
| `WL-check.py` | вся логика (только стандартная библиотека Python) |
| `WL-check-download-python.ps1` | вызывается из `.bat`, **только если Python не найден**: качает портативный Python в `%TEMP%\wlpy` (~11 МБ). В систему ничего не ставит, PATH и реестр не трогает |

Отчёт пишется в `wl-check-result.txt`, при `--json` — ещё и в `wl-check-result.json`.
Код возврата `0`, если живо хотя бы одно зеркало подписки, иначе `1` (удобно для своих скриптов).

Полезные ключи: `--timeout 10` (короче ждать каждый URL), `--json`, `--out путь.txt`.

**Что именно проверяется** (на 2026-10-29 всё это отвечало):

* 6 зеркал подписки `zieng2/wl` — GitHub raw, Githack, Codeberg, GitLab, `hub.mos.ru`, `gitverse.ru`;
  для каждого считается, сколько внутри живых строк `vless://` (зеркало может отдать 200 и заглушку);
* агрегатор `igareck` — README, **CIDR-подписка для белых списков** на Bitbucket, Tor bridges TOP-100;
* три файла `lib4u` для AmneziaVPN;
* если **ни одно** зеркало подписки не ответило — скрипт сам пробует Яндекс Переводчик как прокси
  и печатает готовую ссылку для браузера.
