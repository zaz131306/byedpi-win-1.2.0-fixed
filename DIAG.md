# DIAG.bat — одна команда, и больше от тебя ничего не нужно

```
DIAG.bat
```

Всё. Скрипт сам:

* прочитает конфиг byedpi и покажет, какие аргументы сейчас в силе;
* проверит, запущен ли ciadpi и слушает ли порт;
* посмотрит DNS и как разрешаются имена;
* откроет каждый сайт **напрямую** и **через прокси** и сравнит;
* напишет вывод **словами** по каждому сайту;
* в конце скажет, что делать дальше, конкретными командами.

В конце отчёт сам откроется в Блокноте.

## Что с ним делать

**Перешли мне файл `diag-report.txt` целиком.** Лежит в папке с программой.

Ctrl+A → Ctrl+C → вставить сюда. Или просто приложи файл.

Интерпретировать ничего не нужно — разделы 7 и 10 уже содержат выводы на русском.

## Сколько занимает

1–3 минуты. Окно не закрывай. Проверяется 10 сайтов × 2 способа = 20 замеров.

## Если нужен конкретный сайт

```
python DIAG.py --url https://адрес-который-не-открывается/
```

Он добавится к стандартному набору. Стандартный набор уже включает
`rutor.info` (http и https), зеркала `rutor.is` и `new-rutor.org`,
`flow.google.com`, `google.com`, `youtube.com`, `rutracker.org`,
`instagram.com` и контрольный `gosuslugi.ru`.

## Что означают вердикты в разделе 7

| Вердикт | Что это | Чем лечится |
|---|---|---|
| `НЕ_ЗАБЛОКИРОВАН` | открывается напрямую | ничем, цензуры нет |
| `ОБХОД_РАБОТАЕТ` | закрыт напрямую, открыт через прокси | ничем, уже работает |
| `ПРОКСИ_ЛОМАЕТ` | напрямую работал, через прокси сломался | править аргументы / режим в попапе |
| `ОБХОД_НЕ_ПОДОБРАН` | DPI рвёт, стратегия не подходит | `pick_multi.py` (команда будет в разделе 10) |
| `БЛОКИРОВКА_ПО_IP` | refused сразу, без DPI-разрыва | только туннель: `SYNTH.bat` |
| `НЕТ_ОТВЕТА` | timeout, дроп | белые списки или блок по IP → `SYNTH.bat` |
| `БЛОКИРОВКА_DNS` | домен не разрешается | сменить DNS на 77.88.8.8 / 195.208.4.1 |
| `СОКС_НЕ_РАБОТАЕТ` | сам прокси не отвечает | сначала `fix.bat`, потом диагностика заново |
| `ЗАКРЫТ_БЕЗ_ПРОКСИ` | закрыт, а прокси не запущен | `fix.bat`, затем `DIAG.bat` |

Эта таблица — для меня, не для тебя. Тебе её читать не обязательно:
скрипт печатает нужную строку сам в разделе 10.

## Важное про протоколы

`http://rutor.info/` и `https://rutor.info/` — это **разные** стратегии обхода.
Поэтому скрипт проверяет оба варианта и разбирает их **отдельно**. Картина
«HTTPS открывается, а HTTP нет» (и наоборот) встречается постоянно, и лечится
по-разному: для этого в byedpi есть `--hosts` и `--proto h` / `--proto t`.

Первая версия этого скрипта смотрела «открылся ли хоть один вариант» и на таком
случае выдавала ложное «не заблокировано». Исправлено; регрессию ловит
`test_diag_verdict.py` (12 сценариев, покрывают все 9 вердиктов).

## Безопасность

Скрипт только **читает** конфиг и открывает соединения для замеров.
Ничего не устанавливает, ничего не меняет, ничего не сохраняет, кроме
`diag-report.txt`. Python не обязателен: `DIAG.bat` найдёт его сам или
предложит скачать портативный в `%TEMP%` (и только после твоего «Y»).

## NETSTAT.bat — когда DIAG.bat говорит «подмена DNS»

```
NETSTAT.bat
```

Отвечает на вопрос не «открывается ли сайт», а **что происходит в сети**:
соединения, порты, маршруты, DNS, настройки Firefox, firewall.

Главное, что он умеет: **отличает блокировку от подмены DNS.**

Признак подмены — несколько НЕ связанных между собой доменов разрешаются в ОДИН IP.
Так выглядит «сайт не открывается», когда на самом деле резолвер провайдера
возвращает адрес заглушки вместо настоящего.

| Раздел | Что показывает |
|---|---|
| 1–2 | процессы, кто слушает порт SOCKS5 |
| 3 | все активные TCP-соединения |
| 4–6 | маршруты, адреса интерфейсов, DNS в системе |
| **7** | **сравнение резолверов: системный vs 77.88.8.8 (Яндекс) vs 195.208.4.1 (НСДИ)** |
| **8** | **вывод: есть подмена или нет** |
| 9 | что отдаёт подозрительный IP (заглушка провайдера выглядит узнаваемо) |
| 10 | Firefox: `network.trr.mode` (DoH) и `network.proxy.socks_remote_dns` |
| 11–12 | конфиг byedpi, firewall, антивирус |
| **13** | **вывод словами и пошаговое лечение** |

Опрос конкретных резолверов (77.88.8.8 и 195.208.4.1) идёт **своим DNS-клиентом**
на UDP, а не через системный `getaddrinfo` — иначе всегда спрашивался бы тот самый
резолвер, который и подозреваем во вранье.

Результат — `netstat-report.txt`, открывается сам. Пересылать целиком.

### Почему это важнее, чем кажется

При подмене DNS **обход DPI не помогает в принципе**, даже идеально подобранный.
byedpi маскирует содержимое пакетов, но соединение устанавливается на подменный
адрес — то есть не туда. Поэтому порядок всегда такой: сначала DNS, потом всё остальное.

Две настройки Firefox, которые решают исход:

* `network.trr.mode` = 2 или 3 — DNS через HTTPS, в обход провайдерского резолвера;
* `network.proxy.socks_remote_dns` = **true** — иначе Firefox резолвит домены сам
  (через подменный DNS) и передаёт прокси уже подменный IP. При таком раскладе
  не поможет даже туннель.
