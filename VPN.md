# VPN вместо обхода DPI: AmneziaWG, свой VPS и когда это единственное, что остаётся

Разбор [bivlked/amneziawg-installer](https://github.com/bivlked/amneziawg-installer)
(v6.1.1, MIT, 1430 звёзд, последний коммит 22.10.2026) — и заодно ответ на
ворос «а не проще ли поставить VPN и не мучиться».

Проверено по их `README.md`, `ADVANCED.md`, `WARP-RU.md`, `CASCADE.md`,
`INSTALL_VPS.ru.md`.

---

## 1. Коротко: что это

Одна команда ставит **свой VPN-сервер AmneziaWG** на чистый VPS с Ubuntu 24.04 /
26.04 или Debian 13:

```bash
wget -O install_amneziawg.sh https://github.com/bivlked/amneziawg-installer/releases/latest/download/install_amneziawg.sh
chmod +x install_amneziawg.sh
sudo bash ./install_amneziawg.sh
```

AmneziaWG — форк WireGuard с обфускацией: заголовки шифруются
(`HeaderProtectionKey`), добавляется паддинг внутри и снаружи шифрования,
пакеты-пустышки `Jc` и маскирующий пакет `I1`. Работает в ядре через DKMS, без
Docker и веб-панелей. На выходе — сервер и два клиентских профиля (`my_phone`,
`my_laptop`) с QR-кодами и ссылками `vpn://` в `/root/awg/`.

Их же оценка трудозатрат: 3 команды, 2 перезагрузки по ходу, около 20 минут,
VPS от 512 МБ RAM (комфортно от 1 ГБ), root по SSH. Знать Linux не требуется.

## 2. Главное: это другой класс решения

| | byedpi (этот проект) | AmneziaWG на своём VPS |
|---|---|---|
| что делает | портит пакет так, чтобы фильтр не опознал сайт | уводит **весь** трафик на свой сервер за границу |
| ваш IP видно | да, провайдер его видит | нет, виден IP вашего VPS |
| блок по IP / ASN | **не обходится в принципе** | обходится — именно для этого и нужен |
| блок по TLS-отпечатку | не обходится | обходится |
| подмена сертификата / заглушка | обходится | обходится |
| HTTP и HTTPS | надо подбирать отдельно (`--proto h` / `t`) | всё равно, протокол один |
| подбор аргументов | нужен, под каждого провайдера свой | **не нужен вообще** |
| охват | только Firefox | вся система, все приложения |
| QUIC / HTTP/3 | мимо SOCKS5, надо выключать | идёт через туннель как есть |
| права на ПК | не нужны | **нужны права администратора** (драйвер туннеля) |
| деньги | 0 | VPS, примерно от $3/мес |
| точка отказа | ваш провайдер | ваш провайдер **и** хостер, и AS хостера |

Отсюда практическое правило:

> **Сначала `verify.py`.** Если он показывает `reset`, `mismatch` или
> заглушку `HTTP/1.0` — это лечится аргументами byedpi, VPN не нужен, не
> платите. Если показывает `noconnect` или пишет «ПОХОЖЕ НА БЛОКИРОВКУ ПО IP»
> — аргументов не существует, и VPN (или `transport=tunnel`) это единственное,
> что поможет.

Для вашего случая это значит: rutor.info по HTTP скорее всего чинится byedpi, а
Instagram — нет, потому что Meta заблокирована по IP. То есть **VPN решает ту
половину задачи, которую byedpi решить не может в принципе**, но не заменяет
byedpi там, где хватает десинхронизации.

## 3. Грабли, из-за которых можно заплатить и не получить ничего

Это самое полезное в их репозитории — они честно задокументировали, где схема
ломается.

### 3.1. Блокировка по автономной системе хостера

`ADVANCED.md#as-blocking-adv`. Симптом: рукопожатие проходит, в клиенте
появляется «Последнее рукопожатие», приходит несколько килобайт — и поток
обрывается. Пинг внутри туннеля уходит в 100% потерь. Со стороны выглядит как
«сервер умер», хотя сервер жив и доступен по SSH.

Механизм: фильтрация по **белому списку примерно из 72 AS** (исследование
DPI-аналитика 0ka, [habr.com/ru/articles/997088](https://habr.com/ru/articles/997088/)).
В список **не входят** Hetzner `AS24940`, диапазоны OVH, DigitalOcean, AWS и
Cloudflare — трафик к ним деградирует на уровне ТСПУ.

Важно: обычные junk-параметры `Jc`/`Jmin`/`Jmax` тут **не спасают** — они
меняют сигнатуру пакета, а не адресата по AS.

Их полевая проверка, июнь 2026, чистый сервер на Hetzner, клиент из России,
три московских оператора:

| Оператор | дефолт (`I1 = <r N>`) | QUIC-мимикрия `I1` под SNI `7-zip.org` |
|---|---|---|
| Ростелеком | блок | **заработало**, 0% потерь |
| ecotelecom | блок | **заработало**, 0% потерь |
| Seven Sky | блок | **не помогло** (пробовали два SNI) |

Контроль: туннель к серверу **в другой AS (США)** поднялся и держался на всех
трёх операторах. То есть дело было именно в Hetzner.

Их же вывод дословно: «метод 0ka действительно работает, но не универсально —
результат зависит от оператора и региональной настройки ТСПУ».

**Что из этого следует для вас:**

1. Не берите Hetzner, OVH, DigitalOcean, AWS, Cloudflare — это самые популярные
   у новичков хостеры, и они в списке нерекомендуемых.
2. Перед покупкой проверьте, что VPS вообще доступен из России без VPN:
   откройте его IP в браузере / `ping` / `ssh` с домашнего интернета. Если не
   отвечает — не покупайте.
3. Берите тариф с возможностью вернуть деньги или сменить IP, и **сначала**
   поднимите туннель, а уже потом настраивайте всё остальное.
4. Если рукопожатие проходит, а трафик не идёт — это с высокой вероятностью
   блок по AS, а не кривая настройка. Лечится сменой хостера, не параметрами.

### 3.2. Мобильный интернет: маскирующий пакет режут

`ADVANCED.md#no-hs-mobile-adv`. Симптом: на сотовой сети клиент бесконечно
висит в «Подключении», а **на Wi-Fi тот же профиль работает**.

Ловушка: со стороны сервера это выглядит как живая связь. В `awg show` пир
виден, `endpoint` меняется на мобильный адрес клиента, счётчик байт растёт.
Не обновляется ровно одно поле — `latest handshake`. Транспортные пакеты
проходят, а пакет рукопожатия летит не один: перед ним залп пустышек `Jc` и
маскирующий `I1`. Сеть отбрасывает залп — вместе с рукопожатием.

Установки **до сентября 2026** несут `I1 = <r N>` (N случайных байт), и часть
мобильных сетей такой пакет отбрасывает. С сентября 2026 установщик пишет
вместо него пакет формы DNS-ответа.

Их таблица, как отличить этот случай от соседних:

| что видно на сервере | причина |
|---|---|
| пакетов от клиента нет вообще | не тот порт, фаервол, блок по адресу |
| пакеты есть, `latest handshake` пуст, `endpoint` НЕ меняется | не совпадают `S1`-`S4`, `H1`-`H4` или `HeaderProtectionKey`; либо клиент не понимает 3.1 |
| пакеты есть, `endpoint` меняется, счётчик растёт, `latest handshake` пуст | режут залп — этот случай |

**Что из этого следует:** если у вас мобильный интернет или роутер с 4G —
ставьте сразу с флагом `--mobile` (мобильный пресет обфускации + порт 443/udp
одним флагом). Их список проверенных операторов: Yota, Tele2, Таттелеком/Летай,
Мегафон (с удалённым `I1`), Билайн (дефолт). Домашний проводной интернет, по их
словам, как правило работает «из коробки».

### 3.3. Поколение протокола: 3.1 против 2.0

С версии 6.0.0 новая установка по умолчанию ставит **AmneziaWG 3.1**. Клиент
без поддержки 3.1 профиль 3.1 **не примет**, и ошибки может не быть вовсе —
просто рукопожатия не будет.

Поколение работающего сервера меняется только переустановкой, и все клиентские
профили тогда выдаются заново. Поэтому решать надо **до** установки.

Ставьте `--protocol=2.0`, если среди ваших устройств есть: роутер на стоковой
прошивке (KeeneticOS, OpenWrt со старым пакетом), Hiddify, давно не
обновлявшиеся приложения. На ARM и на ядрах старее 6.7 установщик поставит 2.0
сам.

### 3.4. Реферальная ссылка в рекомендациях хостинга

В разделе «Рекомендация хостинга» их README рекомендует FreakHosting
(тариф BVPS-2, 2 vCPU / 2 GB / 40 GB NVMe, порт 10 Gbps, безлим по трафику,
**€25 в год**) — и это **партнёрская ссылка**: `aff.php?aff=392`, автор
получает процент с заказа. Они это честно пишут, но знать стоит.

Цена €25/год для 2 vCPU и 10 Gbps — подозрительно дёшево. Плюс в их же
`ADVANCED.md` описана блокировка по AS хостера, а для малоизвестного бюджетного
хостера вероятность, что его AS не в белом списке, выше, а не ниже.

Аргумент «их IP не определяются как дата-центровые и не попадают под
блокировки» — ровно то утверждение, которое надо **проверять до оплаты**, а не
после. Конкретно: взять тестовый период или самый дешёвый тариф на месяц,
поднять туннель, убедиться, что он держится с вашего провайдера, и только
потом платить за год.

## 4. Клиент на Windows

Из их таблицы клиентов (снято 15 октября 2026):

| Клиент | AmneziaWG 3.1 | Версия | Где брать |
|---|---|---|---|
| AmneziaWG для Windows (лёгкий) | да | 3.1.0 (21 авг 2026) | страница релизов проекта |
| AmneziaWG для Windows 7 и 8 (сторонняя сборка RomikB) | да | v3.1.1 (28 авг 2026) | релизы проекта, файлы с `windows7` в имени |
| Amnezia VPN (флагман, все платформы) | да | 5.0.3.0 | GitHub, магазины; Windows — прямая ссылка со страницы релизов; **в российском App Store нет** |
| WG Tunnel Desktop (сторонний) | да | v2.4.1 (17 окт 2026) | релизы, `choco`, `apt`, AUR |

Импорт: `my_laptop.conf` из `/root/awg/` на сервере.

**Важно про этот проект:** AmneziaWG — системный туннель, он ставит драйвер и
забирает весь трафик, поэтому нужны права администратора. Расширение byedpi при
включённом VPN лучше **выключить**: два слоя проксирования друг другу не
помогают, а диагностику запутывают так, что концов не найдёте. Если VPN
поднят — в попапе byedpi должно быть выключено, и наоборот.

## 5. Что у них ещё есть полезного

* **`CASCADE.md`** — каскад из двух серверов с раздельным выходом: российский
  трафик идёт через сервер в России (настоящий российский IP), зарубежный —
  через зарубежный. Решает проблему, когда российские сайты (банк, госуслуги,
  маркетплейсы) закрывают доступ адресам зарубежных дата-центров целыми
  диапазонами.
* **`WARP-RU.md`** — то же самое, но на одном сервере: российский сегмент
  уходит через Cloudflare WARP, остальное напрямую. Список российских сетей
  сервер получает по BGP от antifilter.network (~11800 префиксов, обновляются
  сами). Требует `wgcf`, BIRD, свободную таблицу маршрутизации 200 и
  регистрацию внешнего IP в antifilter.network. Это **надстройка**, в
  установщик не входит, и это уже уровень «я понимаю, что делаю».
* **`manage_amneziawg.sh`** — `add` / `remove` / `regen` / `check`: добавить
  устройство или друга одной командой, клиенту со сроком действия
  (`--expires=7d`).
* **Подпись minisign** установщика и зашитые в него SHA256 тех скриптов,
  которые он качает сам (`awg_common`, `manage`) — берёт с тега своей версии и
  сверяет. Неплохая практика, можно проверить до запуска.
* **197 файлов тестов** (bats + ShellCheck в CI), `.gitattributes`,
  `.editorconfig`, отдельная папка `signing/`. Проект живой и ухоженный, не
  поделка на коленке.

## 6. Порядок действий, если решите ставить

```text
1. python host\verify.py                       <- сначала! см. раздел 2
   Если всё «reset» / «mismatch» / заглушка -> VPN не нужен, чинится byedpi.
   Если «noconnect» / «ПОХОЖЕ НА БЛОКИРОВКУ ПО IP» -> дальше имеет смысл.

2. Выбрать хостера. НЕ Hetzner, OVH, DigitalOcean, AWS, Cloudflare.
   Проверить доступность IP из России БЕЗ VPN до оплаты.
   Взять месяц, не год.

3. Ubuntu 24.04 или Debian 13, x86_64, от 1 ГБ RAM, root по SSH.

4. Мобильный интернет или 4G-роутер -> добавляем --mobile.
   Есть роутер на стоковой прошивке / Hiddify / старые приложения
   -> добавляем --protocol=2.0. Решить ДО установки.

5. wget -O install_amneziawg.sh <ссылка на последний релиз>
   sha256 / minisign сверить до запуска.
   sudo bash ./install_amneziawg.sh [--mobile] [--protocol=2.0]
   Две перезагрузки: на каждом вопросе о перезагрузке отвечать y и запускать команду снова.

6. Windows: поставить AmneziaWG 3.1.0 (или Amnezia VPN), импортировать
   /root/awg/my_laptop.conf. Расширение byedpi ВЫКЛЮЧИТЬ.

7. Проверить: рукопожатие есть, трафик идёт, IP сменился.
   Если «рукопожатие прошло и тишина» -> см. раздел 3.1, это AS хостера.
   Если на сотовой висит, а на Wi-Fi работает -> см. раздел 3.2.

8. Только потом платить за год и добавлять остальные устройства.
```

## 7. А если VPS не хочется

В этом проекте уже есть `transport=tunnel` (см. `tunnel/README.md`): свой
шлюз, браузерный туннель, трафик прячется внутри обычного WSS-соединения с
вашим сайтом. Снаружи это просто HTTPS на 443.

Сравнение честное:

| | `transport=tunnel` | AmneziaWG |
|---|---|---|
| нужен сервер | да, с доменом и сертификатом | да, VPS |
| права на ПК | не нужны | нужны |
| охват | только Firefox | вся система |
| скорость | ниже: WSS поверх TLS, userspace | выше: WireGuard в ядре |
| блокируется | как любой HTTPS-туннель на ваш домен | по AS хостера и по форме пакета |
| настройка | своя, в этом проекте | одна команда |

Если сервер всё равно нужен, AmneziaWG быстрее и закрывает всю систему. Если
сервера нет и покупать не хочется — `transport=tunnel` тоже не вариант, тогда
остаётся обычный коммерческий VPN, и там уже смотрите на то, работает ли он из
России и не заблокирована ли AS провайдера.

## 8. Другой случай: режим «белых списков»

Выше речь про фильтрацию по AS (~72 белых автономные системы). Есть ещё один, более жёсткий
режим, который включают на мобильном интернете и в отдельных регионах: пропускают **только**
разрешённые сайты и IP, всё остальное не работает вообще.

Признаки:

* не открывается почти ничего, а «одобренное» (Госуслуги, банки, российские сервисы) — открывается;
* один и тот же VPN-конфиг работает на домашнем Wi-Fi и **не** работает на мобильном;
* зависит от региона и оператора, включается волнами.

В этом режиме **бесполезны и byedpi, и обычный VPN-конфиг на случайном иностранном IP** —
фильтр не даёт соединению установиться, маскировать нечего. Нужен канал, который сам проходит
через белый список: VLESS-REALITY с SNI белого российского домена, выход через подсети
VK/Яндекса/CDNVIDEO, xhttp через CDN, или DNS-туннель как крайняя мера.

**Всё это разобрано отдельно, с живыми ссылками и проверкой на работоспособность:
см. `WHITELIST.md`.** Там же скрипт `WL-check.bat`, который покажет, какие зеркала подписок
отвечают прямо сейчас (ссылки протухают за часы).
