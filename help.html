Byedpi SOCKS5-прокси · обход DPI

Расширение Firefox + локальный менеджер, который запускает движок ciadpi (byedpi) и направляет трафик браузера через SOCKS5 на 127.0.0.1:1080. Прав администратора не требует, VPN не поднимает — только прокси для Firefox.

1. Как это устроено

Firefox (расширение)
   │  browser.proxy.settings → SOCKS5 127.0.0.1:1080, DNS через прокси
   │
   ├─ Native Messaging (stdio, JSON) ──► host/native_host.py   (тонкий мост)
   │                                          │  TCP 127.0.0.1 + токен
   │                                          ▼
   │                                     host/manager.py       (демон, владеет процессом)
   │                                          │  subprocess.Popen
   │                                          ▼
   │                                     bin/ciadpi -i 127.0.0.1 -p 1080 <стратегия>
   │                                          ▲
   └─ трафик SOCKS5 ──────────────────────────┘

Параллельные клиенты того же менеджера:
   • host/ctl.py        — консоль
   • web-интерфейс      — http://127.0.0.1:8787/?t=<токен>

SOCKS5-протокол реализован внутри ciadpi — своё мы не пишем. Менеджер вынесен в отдельный процесс специально: «засыпание» event-page расширения или закрытие попапа не обрывает прокси. Если клиентов не было stop_after_disconnect_sec секунд (по умолчанию 60), прокси аккуратно гаснет.

2. Установка (3 шага)

Шаг 1. Требования

  • Firefox 109+ (также работает в LibreWolf, Waterfox, Floorp).
  • Python 3.8+ (только стандартная библиотека, никаких pip-пакетов). В Windows при установке Python отметьте Add python.exe to PATH.
  • Windows 10/11 x64, Linux x86_64/i686/ARM или macOS (для macOS бинарник нужно собрать вручную, см. ниже).

Шаг 2. Скачать ciadpi и зарегистрировать хост

Одной командой:

# Windows
install.bat

# Linux / macOS
chmod +x install.sh && ./install.sh

Скрипт сделает то же, что и команды вручную:

python host/download_ciadpi.py      # готовый бинарник из релизов hufrea/byedpi → bin/
python host/ctl.py install          # манифест native-messaging хоста для Firefox
python host/ctl.py install --check  # проверить, что всё встало

Бинарник не компилируется и не встраивается в exe — он лежит отдельным файлом в bin/, его легко заменить или обновить.

macOS: готовых сборок в релизах нет, соберите сами и укажите путь:

git clone https://github.com/hufrea/byedpi && cd byedpi && make
python host/ctl.py set binary=/путь/к/byedpi/ciadpi

Шаг 3. Загрузить расширение в Firefox

  1. Откройте about:debugging → слева Этот Firefox (This Firefox).
  2. Нажмите Загрузить временное дополнение… (Load Temporary Add-on).
  3. Выберите файл addon/manifest.json в каталоге проекта.
  4. На тулбаре появится иконка — нажмите её и жмите Подключить.

Временное дополнение снимается после перезапуска Firefox — для постоянной установки нужен подписанный .xpi: python host/ctl.py install --extension упакует и положит его в профиль (неподписанные xpi ставятся только в Nightly/ESR с xpinstall.signatures.required=false).

3. Настройка Firefox

Вариант А (по умолчанию). Расширение прописывает прокси само: достаточно нажать Подключить. В статусной строке попапа появится сообщение «Firefox направлен через SOCKS5 127.0.0.1:1080 (DNS через прокси)».

Вариант Б (вручную). Если автоматика не сработала или вы хотите настроить сами:

  1. Нажмите Подключить в попапе (или python host/ctl.py start).
  2. Firefox → Настройки → Основные → блок Параметры сети → Настроить…
  3. Выберите Ручная конфигурация прокси (Manual proxy configuration).
  4. В поле SOCKS-узел (SOCKS Host) впишите 127.0.0.1, порт 1080.
  5. Версия прокси: SOCKS v5.
  6. Обязательно включите ☑ Проксировать DNS при использовании SOCKS v5 (Proxy DNS when using SOCKS v5) — иначе DNS-блокировки не обойдутся.
  7. Поля HTTP/HTTPS прокси оставьте пустыми. В «Не использовать прокси для» можно оставить localhost, 127.0.0.1, ::1.
  8. OK.

Оставшиеся пустыми поля HTTP-прокси означают, что весь трафик идёт через SOCKS5.

4. Обязательно: отключить HTTP/3 (QUIC)

QUIC — это UDP. Он не проходит через SOCKS5-прокси, поэтому часть сайтов продолжает открываться напрямую и блокируется, а часть — «виснет».

  1. Откройте about:config, примите предупреждение.
  2. Найдите network.http.http3.enable и переключите в false.
  3. Перезапустите Firefox.

То же самое одной командой (правит user.js в профиле):

python host/ctl.py install --userjs

Дополнительно можно выставить network.dns.http3_echconfig.enabled = false и network.http.http3.enable_quic = false — скрипт это делает.

5. Стратегии обхода DPI

Стратегия = набор аргументов ciadpi. Переключается в попапе или командой python host/ctl.py set strategy=fake. Прокси перезапускается автоматически.

IDЧто делаетАргументы (Linux / Windows)
recommendedДесинхронизация + авто-переход на tlsrec при признаках блокировки. Начинайте отсюда. --disorder 1 --auto=torst --timeout 3 --tlsrec 1+s
--split 1+h --disorder 3+h --auto=torst --timeout 3 --tlsrec 1+s
fakeПоддельный TLS ClientHello, который не доходит до сервера. --fake -1 --md5sig
--disorder 1 --fake -1
fake-ttlТо же, но фейк гаснет по TTL. Универсальный вариант.--fake -1 --ttl 8
disorderНарушение порядка сегментов.--disorder 1
--split 1+h --disorder 3+h
oobВнеканальный байт внутри SNI.--auto=torst --timeout 3 --oob 3+h
tlsrecРазбиение TLS-записи, заголовок вставляется в середину SNI.--auto=torst --timeout 3 --tlsrec 3+s
aggressiveНесколько групп подбора — ciadpi перебирает их сам.см. попап
universalКак recommended, но правила привязаны флагом +h — он работает и для TLS (позиция SNI), и для обычного HTTP (заголовок Host). Плюс --mod-http h.--split 1+h --disorder 1 --mod-http h --auto=torst --timeout 3 --tlsrec 1+s
--split 1+h --disorder 3+h --mod-http h --auto=torst --timeout 3 --tlsrec 1+s
httpТолько HTTP: +h плюс --mod-http h.--split 1+h --disorder 3+h --mod-http h
ladderЧетыре группы, ciadpi перебирает их сам по триггеру --auto=torst. Нужен там, где DPI инжектит RST.см. host/strategies.py
plainЧистый SOCKS5 без обхода. Нужен для диагностики.—
customВаши аргументы из поля «Свои аргументы ciadpi».что вписали

Подбор конкретных параметров под провайдера — это всегда эксперимент. Порядок действий: recommended → universal → ladder → fake-ttl → python host/ctl.py pick --url САЙТ. Если verify.py пишет «ПОХОЖЕ НА БЛОКИРОВКУ ПО IP» — аргументов ciadpi для такого сайта не существует вовсе, нужен туннель: см. VPN.md (AmneziaWG на своём VPS, с разбором граблей) и tunnel/README.md. pick подбирает под один сайт и пишет победителя глобально — YouTube откроется, а трекер и Instagram нет. Чтобы у каждого домена была своя стратегия, нужен python host/pick_multi.py --url http://rutor.info/ --url https://www.instagram.com/ --url https://www.youtube.com/ --apply -y: он подбирает по каждому адресу отдельно и склеивает победителей в доменные группы --hosts + --proto. Флаг +s привязывает правило к SNI и на обычном HTTP не срабатывает вовсе — для HTTP нужен +h, он покрывает оба протокола. Комбинации +sh в byedpi не существует: парсер молча превращает её в +s. Полный список флагов: bin/ciadpi --help и README byedpi.

Список кандидатов для автоподбора (host/strategy_candidates.txt) взят из Android-приложения ByeByeDPI x tg (GPL-3.0), их файл proxytest_strategies.list, и доработан: исправлены флаги с молча отбрасываемым хвостом, добавлены кандидаты для обычного HTTP и дефолт самого приложения (-o1 -a1 -r-5+se), строки пересортированы так, чтобы первыми шли работающие на обоих протоколах. Сравнение подходов — в FIX.md, раздел 12: у них весь трафик забирает Android VpnService (TUN), здесь расширение Firefox работает без прав администратора и видит только браузер; подбор стратегий у них тоже есть, просто спрятан за кнопку «Проверка стратегий».

6. Команды консоли (ctl.py)

python host/ctl.py status                 # состояние, адрес, pid, стратегия
python host/ctl.py start                  # запустить ciadpi
python host/ctl.py stop                   # остановить и освободить порт
python host/ctl.py restart                # перезапустить
python host/ctl.py selftest --start       # порт → SOCKS5 → реальный HTTPS-запрос
python host/ctl.py logs -f                # журнал ciadpi в реальном времени
python host/ctl.py args                   # итоговая командная строка ciadpi
python host/ctl.py info                   # бинарник, платформа, web-интерфейс
python host/ctl.py set port=1081          # сменить порт (прокси перезапустится)
python host/ctl.py set strategy=fake      # сменить стратегию
python host/ctl.py set advanced.debug_level=2   # подробный лог ciadpi
python host/ctl.py get                    # показать config.json
python host/ctl.py webui --open           # локальная веб-панель управления
python host/ctl.py run                    # менеджер в этом терминале (Ctrl+C — стоп)
python host/ctl.py shutdown               # остановить менеджер и прокси
python host/ctl.py install --autostart    # хост + автозапуск при входе в систему
python host/ctl.py doctor --url САЙТ      # вся диагностика: хост, порт, TLS, пробы по сайтам
python host/pick_multi.py --url A --url B --apply -y  # подбор под каждый сайт, группы --hosts
python host/check_tls.py                  # какие корневые CA видит Python
python host/verify.py --quick             # что РЕАЛЬНО работает: напрямую против через прокси
fix.bat                                   # всё сразу: проверка → подбор под каждый сайт → перепроверка

7. Самопроверка

Полный набор проверок (соответствует разделу «что должно работать»):

python tests/run_all.py

Проверяется: наличие бинарника, запуск и появление слушающего порта, корректность SOCKS5-handshake, реальный запрос через прокси, остановка и освобождение порта, отсутствие «зависания» при выключенном прокси, идемпотентность повторного старта, поведение при занятом порте, сохранение настроек, протокол native-messaging, синтаксис JS расширения и валидность manifest.json.

Быстрая ручная проверка:

python host/ctl.py start
python host/ctl.py selftest https://www.google.com/
python host/ctl.py stop

8. Если не работает

СимптомЧто делать
В попапе «Native-messaging хост не установлен» Выполните python host/ctl.py install, затем полностью перезапустите Firefox (все окна). Проверьте install --check: путь в манифесте должен существовать.
Бейдж «!», ciadpi не найден python host/download_ciadpi.py или укажите путь: ctl.py set binary=…. На macOS бинарник собирается вручную.
Порт уже занят ctl.py set port=1081, либо закройте другое приложение (часто 1080 занимают Tor/other proxy). В Windows: netstat -ano | findstr :1080.
Прокси работает, но сайты не открываются Отключите HTTP/3 (раздел 4). Попробуйте другую стратегию. Проверьте ctl.py selftest: если он проходит, а браузер нет — дело в настройках Firefox.
Часть сайтов открывается, часть нет Почти всегда HTTP/3/QUIC или DoH. Отключите network.trr.mode = 5 (или 2 → 5) и network.http.http3.enable = false.
Всё висит при выключенном прокси Firefox ждёт ответа от мёртвого прокси ~30 с. Нажмите «Отключить» в попапе — расширение снимет настройки прокси, и браузер вернётся к прямому соединению.
Антивирус/SmartScreen ругается на ciadpi Это ложное срабатывание на инструмент модификации трафика. Файл берётся из официальных релизов hufrea/byedpi; SHA256 записывается в bin/VERSION.json.
Ничего не понятно ctl.py set advanced.debug_level=2 → ctl.py restart → ctl.py logs -f. Плюс лог менеджера в каталоге настроек (ctl.py info).

├── addon/                  расширение Firefox (manifest v3)
│   ├── manifest.json       ID: byedpi-control@byedpi.local
│   ├── background.js       native-порт, browser.proxy.settings, бейдж
│   ├── popup.html/css/js   панель управления

├── host/                   Python-часть (только стандартная библиотека)

│   ├── config.py           настройки (config.json)
│   ├── strategies.py       пресеты аргументов обхода
│   ├── netutil.py          проверки порта, SOCKS5-клиент, self-test
│   ├── procutil.py         PID/lock/запуск detached
│   ├── install.py          регистрация хоста, автозапуск, user.js, xpi
│   ├── download_ciadpi.py  скачивание бинарника из релизов
│   └── webui.py            локальная веб-панель
├── bin/                    ciadpi (скачанный бинарник) + VERSION.json
├── tests/                  проверки и интеграционный прогон
├── install.sh / install.bat
└── README.md

Пользовательские файлы (не в каталоге проекта):

  • Windows %APPDATA%\byedpi-firefox\
  • Linux ~/.config/byedpi-firefox/
  • macOS ~/Library/Application Support/byedpi-firefox/

Там лежат config.json (настройки), manager.lock (PID/токен/порт control-сокета), status.json, ciadpi.log, manager.log, webui.url.

10. Удаление

python host/ctl.py shutdown              # остановить прокси и менеджер
python host/ctl.py install --uninstall   # убрать манифест хоста, автозапуск, наши строки в user.js

Затем удалите расширение в about:addons и, при желании, каталог проекта и ~/.config/byedpi-firefox/ (или %APPDATA%\byedpi-firefox\).

11. Безопасность

  • Прокси слушает только loopback (127.0.0.1) — из сети к нему не подобраться. Прав администратора не требуется.
  • Control-сокет менеджера тоже на loopback и защищён случайным токеном из manager.lock (права 0600).
  • Web-интерфейс открывается только по ссылке с токеном; без токена — 403. Команда shutdown из веб-панели запрещена.
  • Расширение не запрашивает доступ к содержимому страниц и ничего не отправляет наружу: весь обмен идёт с локальным процессом.
  • Бинарник ciadpi берётся из официальных релизов; SHA256 пишется в bin/VERSION.json.
  • Инструмент модифицирует TLS-трафик для обхода блокировок. Используйте на своё усмотрение и с учётом законодательства вашей страны.
